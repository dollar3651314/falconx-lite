# 报价源接入：AllTick（主）和 iTick（备）
- 版本：v1（2026-10-17）
- 编写：研发
- 状态：**方案 + 代码已完成，等 Amos 审核；两家都还没有 token，真实连接"未验证，等 token"**
- 背景：Amos 2026-10-17："先把推荐的两个报价源接上，我去谈合作"。选型依据是 2026-10-16 的报价源调研（结论：AllTick 主、iTick 备，两家都覆盖 50 个品种，但标准条款都禁止未授权的再分发 / 公开展示，见第 6 节）。
- 底线：**token 只由 Amos 填进服务器 `.env`**，仓库、对话、日志里都没有 token 的值；代码只定义变量名（第 7 节）。
- 只要报价，**不抛单**（不向任何一家下单，两家也没有下单接口）。
- 标注口径（规则 C66）：**【证实】** = 打开过官方文档或实际调用过；**【推断】** = 根据资料推理；**【未查到】** = 查了没找到。出处写在每行后面。

## 0. 一句话
每个品种配置"主源、备源"（默认 AllTick 主、iTick 备，写在 `application.yml`）；**哪家没配 token 就当它不存在**，两家都没配的品种继续用模拟源，所以现在（没有任何 token）行为和以前完全一样。主源一个品种 10 秒没报价就切到备源，恢复 30 秒后切回；两家同时有价且相差超过 0.5% 时这个品种的报价判为异常（不能成交）并进 E8 告警。官网 `/api/public/quotes` 默认**只显示模拟价（"示例行情"）**，拿到展示授权后改 `FX_PUBLIC_QUOTES_SOURCE=live`。

## 3. 按品种选报价源

### 3.1 配置放在哪里：配置文件（不放数据库）
- 映射写在 `application.yml`（随代码走 PR 审核，每个环境一样），token 和地址走环境变量。
- 不放数据库的理由：映射跟着和数据商签的合同走，很少改；放数据库要加迁移、后台页面、权限点、审计，改错一个代码就会让真实品种断价，而配置文件的改动有 PR 记录、有测试检查（启动时校验格式，见 `QuoteFeedsProperties`）。
- 代价：后台新增的品种（E3）没有映射，在模拟模式下继续走模拟源，在 `live` 模式下没有报价；要接真实报价要改 `application.yml` 并发布。

### 3.2 三种报价模式（`FX_MARKET_SOURCE`）
| 值 | 用在哪里 | 行为 |
|---|---|---|
| `none`（代码默认） | 后端测试 | 不启动任何报价源（和以前一样） |
| `simulated`（测试环境默认） | 开发、测试环境 | **配了 token 的报价源接管它覆盖的品种，其余品种继续模拟**。两家都没配 token 时和以前完全一样 |
| `live`（新增） | 以后的生产 | 只用真实报价源；没有可用真实源的品种没有报价（不能成交），**绝不会用模拟价成交** |

一个品种只要有一个配了 token 的源，它的交易报价就只来自真实源，模拟源不再给它送交易价（避免真实价和模拟价来回跳，触发质量守卫"单次跳变 10%"）。真实源全断时，这个品种在"行情断流"告警和质量守卫下变成不可成交，不会退回模拟价。

### 3.3 可插拔
报价源是 `QuoteFeed`（名字 + 连接状态），WebSocket 的连接、心跳、重连、重新订阅都在共用的 `WsFeed` 里；AllTick、iTick 各自只写"握手怎么带 token、订阅和心跳消息怎么拼、推送怎么解析"。以后加 OKX（加密货币第三源，Amos 2026-10-17 说会去谈授权）：新写一个 `WsFeed` 子类、加一组 `FX_QUOTE_OKX_*` 变量，在映射里给 10 个加密货币加上 `okx:…`，主备逻辑不用改。这次不实现 OKX。

## 4. 主备切换和交叉校验（`QuoteRouter`）
每个品种记下每个源最后一条报价（价格 + 收到时间），只把"当前使用的源"的报价交给行情主链路（交易时段 → 质量守卫 → 加点 → …，不变）。

- **切到备源**：当前用主源，主源这个品种超过 `FX_QUOTE_FAILOVER_AFTER`（默认 10 秒）没报价，而备源有新报价 → 切到备源。记日志、告警项 `quote.failover` 变 DOWN。
- **切回主源**：主源重新连续报价满 `FX_QUOTE_FAILBACK_AFTER`（默认 30 秒，防止来回切）→ 切回主源。
- 切换不靠定时器：每条报价进来时判断，所以只看内存、不额外占线程。
- **交叉校验**：两家这个品种的最新报价都在 5 秒内时，算中间价偏差 `|主 − 备| ÷ 备`；超过 `FX_QUOTE_MAX_DEVIATION`（默认 0.005 = 0.5%）→ 这个品种进入"报价源偏差"状态：
  - 行情主链路在质量守卫**之前**把它判为 `ABNORMAL`（`QuoteProcessor` 新加的一层）：**不能成交**——不能开仓，也不触发挂单、止盈止损、强平；客户端显示不可交易。
  - 为什么不只"暂停开仓"：两家对不上时不知道哪个对，如果只停开仓，平仓、止损、强平还会按可能错误的价格成交，损失更大。代价是这段时间客户也不能平仓。**需要 Amos 确认**（第 11 节 Q1）。
  - 偏差回到阈值以内（两家都有新价时）自动恢复；一边没有新价（例如备源断了）无法校验时也恢复（只剩一个源，照常报价，但 `quote.itick` 等告警会亮）。
  - 告警项 `quote.deviation` 变 DOWN，详情列出品种和偏差。
- 只有一个源的品种（US2000、或只配了一家 token）不做交叉校验。

## 5. 安全默认、告警和指标

### 5.1 没有 token：和现在完全一样
两家的 token 变量都是空的默认值。空 token 的报价源不创建连接、不出现在健康检查、不出现在指标里；所有品种都是模拟源（`simulated` 模式）。后端测试（`none`）也不变。

### 5.2 配了 token 但连不上
- 连接失败、握手 401、被服务器断开、超过 60 秒没收到任何消息（含心跳回应）→ 断开重连，**指数退避**：1、2、4、8……秒，最长 60 秒，带少量随机抖动；连上并收到第一条数据后退避清零。重连后自动重新订阅（AllTick 的订阅本来就是"整份覆盖"，iTick 在鉴权成功后订阅）。
- **健康检查的 `status` 不受影响**（约定 24：外部服务的故障不能让部署回滚）；只进 E8 业务告警：

| 告警项（`alerts` 里的名字） | 什么时候有 | DOWN 的条件 |
|---|---|---|
| `quote.alltick`、`quote.itick` | 这家配了 token | 有连接没连上，或者连上了但开市的品种超过 60 秒没收到这家的任何报价 |
| `quote.failover` | 配了两家 | 有品种正在用备源 |
| `quote.deviation` | 配了两家 | 有品种因为两家价格偏差暂停成交 |
| `market`（已有） | 有报价源 | 开市的品种全部 30 秒没报价 |

告警邮件照原来的规则发（同一项 30 分钟内不重复）。详情里写每条连接的状态和最后的错误，**不写 token**（AllTick 的地址带 token，日志和告警里只写去掉参数的地址）。

### 5.3 指标（E10，`/actuator/prometheus`，只在 127.0.0.1:8081）
- `fx_quote_feed_connected{feed,channel}`：1 已连上、0 没连上
- `fx_quote_feed_messages_total{feed}`：收到的消息数（含心跳回应）
- `fx_quote_feed_quotes_total{feed}`：解析出的报价数
- `fx_quote_feed_reconnects_total{feed}`：重连次数
- `fx_quote_feed_last_message_age_seconds{feed}`：最后一条消息距今秒数
- `fx_quote_route_backup`：正在用备源的品种数；`fx_quote_route_deviation`：因偏差暂停成交的品种数
- 已有的 `fx_quote_age_seconds{symbol}`、`fx_quotes_received_total` 不变。

### 5.4 价格换算：小数位、加点、USDT
- **小数位**：数据商的价格可能比品种的报价小数位（`market_symbol.digits`）多。进主链路前按 digits 取整：买价（bid）向下、卖价（ask）向上（只会让点差变宽，不会变窄）。
- **加点**：照旧只在主链路加一次（约定 10），值是后台品种的 `markup`（现在都是 0）。真实源的点差是数据商的原始点差，**Amos 要决定各品种加多少点**（第 11 节 Q2）。
- **USDT = USD**：两家的加密货币都是 USDT 计价，我们的品种是 `XXXUSD`。**Amos 已确认按 1:1（2026-10-17）**，仍然做成可配置：`FX_QUOTE_USDT_USD_RATE`（默认 1），只作用于代码以 `USDT` 结尾的映射。

### 5.5 后台品种页
品种列表接口多两个字段：`quoteSource`（`alltick` / `itick` / `simulated` / 空）和 `quoteSourceState`（`primary` 主源 / `backup` 正在用备源 / `deviation` 偏差暂停 / 空）。品种页"最后报价时间"一列旁边显示当前报价源（例如"AllTick"、"iTick（备）"、"模拟"），偏差暂停时标红。

## 6. 官网和客户端的展示（条款风险，重要）
- 两家条款原文：AllTick "You must not redistribute information displayed on or provided by AllTick"，并写明数据"not intended for trading or investing purposes"；iTick "Redistribution without permission is prohibited"、未经事先书面授权不得以任何媒介复制或分发【证实，[AllTick 条款](https://alltick.co/terms)、[iTick 条款](https://itick.org/en/terms)，见调研报告】。
- **官网 `GET /api/public/quotes`（不登录）默认不展示真实报价源的价格**：新开关 `FX_PUBLIC_QUOTES_SOURCE`：
  - `simulated`（默认）：官网每个品种都取模拟价。真实源接管的品种，模拟源仍在后台随机游走，但价格只放在一份单独的"示例行情"里，**不进交易链路**；官网照旧显示"示例行情"（`sample: true`）。
  - `live`：官网取交易用的报价（真实源的价格）。**拿到两家书面的公开展示授权以后才能打开**。
- **客户端（登录后）的报价也是"展示给客户"**：客户端的行情、K 线、下单价格就是交易用的报价，没有单独的开关（不能给客户看一个价、按另一个价成交）。所以：
  - 测试环境内部验收（只有我们自己的账号）用试用 token 一般可以，但严格说也要看条款（AllTick 一周试用、iTick 免费档"仅限个人"），注册时问清楚。
  - **生产必须先拿到两家的书面授权**（覆盖"作为差价合约报价基准"和"向终端客户实时展示"两项），然后才能把 token 填进生产。已写进第 11 节和交付提醒。
